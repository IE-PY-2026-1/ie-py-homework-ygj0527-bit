## 🟩 [2차 과제: V1.0] 입출력 + 리스트 + 조건문 - 향후 작성 예정

  * **다중 계층 선택 시스템** :if-elif-else를 이용한 **계층형 선택 구조**를 통해 다층 구조의 도서관 공간을 효율적으로 탐색하도록 설계했습니다. 특히 and/or/not 등의 논리 연산자를 복합적으로 구성하여, 좌석 번호의 유효 범위 검증과 기존 예약 데이터와의 중복 여부를 동시에 판정하는 고도화된 예약 승인 로직을 구현했습니다.

### **🛠️ Troubleshooting & 기술 회고:**

1. **문제 1: 입력 데이터의 엄격한 자료형 구분 (TypeError)**
    * **원인:** input() 함수는 모든 데이터를 문자열(Unicode String)로 수신하기 때문에, 학번 합계나 이용 시간 차이 계산 시 TypeError가 발생하며 프로그램이 강제 종료되었습니다.
    * **해결:** 각 데이터의 성격에 맞춰 **명시적 형변환**을 수행했습니다. 식별자는 int(), 정밀한 수치는 float()로 래핑하여 산술 연산의 안정성을 확보했으며, 이 과정에서 파이썬의 동적 타이핑 특성과 형변환의 중요성을 깊이 이해하게 되었습니다.
2. **문제 2: 논리 구조의 완결성을 위한 구문 제어 (SyntaxError)**
    * **원인:** 복잡한 조건문과 반복문이 중첩되면서 코드 블록의 시작점인 콜론(:)을 누락하거나, 파이썬 특유의 들여쓰기 규칙이 어긋나 IndentationError 및 SyntaxError가 빈번히 발생했습니다.
    * **해결:** 코드 편집기의 린팅 기능을 활용하여 모든 제어문 끝에 콜론 기호를 확인하고, 논리적 위계에 따른 코드 블록 정렬을 전수 점검했습니다. 특히 중첩 if문 내에서의 코드 흐름을 시각적으로 구조화하여 가독성과 실행의 완결성을 높였습니다.

 1. **내용 1: 절차지향성 코드의 모듈화 및 전역 변수(global) 참조 구조 최적화**

### **🛠️ Troubleshooting & 기술 회고:**
  1. **문제 1: 함수 내 전역 리스트 수정 시 발생한 로컬 참조 오류 (UnboundLocalError)**
     * **원인:** reserve_seat() 함수 내부에서 기존 예약자 명단 리스트에 새로운 좌석을 .append()하거나 정렬.sort()하려고 시도했을 때, 파이썬 컴파일러가 해당 리스트를 함수 내부에서 새롭게 정의된 지역 변수(Local Variable)로 오인하여 외부의 전역 데이터를 참조하지 못해 에러가 발생했습니다.
     * **해결:** 함수 블록이 시작되는 최상단에 global reserved_seats 키워드를 선언하여 컴파일러에게 이 변수가 프로그램 최상위 레이어에 존재하는 전역 변수임을 명시해 주었습니다. 이를 통해 변수의 유효 범위(Scope)를 명확히 제어하며 리스트를 안전하게 조작할 수 있었습니다.
  2. **문제 2: 무한 루프 내 예외 입력 처리 시 제어 흐름 이탈 현상 (Logical Error)**
     * **원인:** while True 루프 내부에서 사용자가 지정된 메뉴 번호(1~4) 외에 잘못된 문자나 범위를 벗어난 숫자를 입력했을 때, 세션이 초기화되거나 다음 반복 흐름으로 매끄럽게 넘어가지 못하고 예약 프로세스가 강제로 시작되는 등의 제어 구조 꼬임 현상이 발견되었습니다.
     * **해결:** 메인 루프 내부의 조건 필터를 구조화하여 올바르지 않은 입력이 들어올 경우 else: 블록을 통해 예외 안내 문구를 출력한 뒤, 하위 함수들을 호출하지 않고 다시 while문의 초입으로 돌아가 대기하도록 제어 위계를 재정렬했습니다. 또한 종료 메뉴 선택 시에만 정확히 break가 트리거되도록 구조적 무결성을 확보했습니다.

도서관 입구에 설치되어 사용자에게 프로그램의 목적을 알리는 안내 문구를 시작으로, 이용자의 이름과 학번을 입력받습니다. 원하는 열람실 층수와 세부 구역, 좌석 번호를 지정한 뒤 입실 및 퇴실 예정 시간을 시/분 단위로 각각 구분하여 입력합니다. 
입력이 완료되면 시스템은 입력 데이터를 바탕으로 좌석 예약 완료 문구와 함께 예약 확인서를 결과 화면에 시각적으로 출력합니다. 이용자는 시스템 메뉴를 통해 실시간으로 현재 시각을 입력하여 퇴실까지 남은 잔여 시간(n시간 n분 형태)을 언제든지 조회할 수 있습니다. 
특히 V4.0 버전에서는 다중 사용자 데이터를 누적 관리할 수 있는 이중 리스트 구조, 프로그램 종료 시 데이터 휘발을 방지하는 파일 자동 저장 시스템, 사용자의 잘못된 입력값이나 파일 부재 상황에서도 시스템이 다운되지 않는 try-except 예외 처리 구조를 확장 반영하여 독창성과 안전성을 확보했습니다.
* **선형 데이터에서 다차원 구조로의 확장 (이중 리스트) :** 1인의 단일 예약 세션 정보만 일회성으로 관리하던 전역 변수 체계를 확장하여, 복수 사용자의 예약 명단을 행(Row) 단위로 누적하는 이중 리스트(`all_reservations`) 구조를 설계했습니다. 이를 통해 시스템 내 데이터 적재 능력을 2차원 매트릭스 형태로 고도화했습니다.
* **다차원 배열의 제어 및 이중 순회 출력 :** 중첩 `for`문 아키텍처와 리스트 인덱싱을 융합하여 이중 리스트 내부에 캡슐화된 개별 요소들을 행과 열 단위로 분해했습니다. 이를 가로형 마스터 테이블 포맷(`f-string` 정렬)으로 시각화하여 데이터의 가독성을 극대화했습니다.
* **영속성 컨텍스트 구현 (파일 입출력) :** 프로그램 종료 시 RAM 내의 데이터가 휘발되는 한계를 극복하기 위해 `with open()` 컨텍스트 매니저를 도입했습니다. 시스템 안전 종료(메뉴 4번) 트리거 시, 적재된 이중 리스트 데이터를 CSV 스타일(콤마 구분자) 스트림으로 변환하여 `reservation_log.txt`에 영구 저장(Write)하는 메커니즘을 구축했습니다.
* **견고성 확보를 위한 예외 처리 시스템 :** 외부의 잘못된 입력값이나 형식 오류로 인해 런타임 환경이 붕괴되는 것을 방지하기 위해 최소 2곳 이상의 핵심 입력 및 출력 파이프라인에 `try-except` 블록을 구성했습니다. `ValueError` 등의 예외를 가로채어 프로그램 비정상 종료를 완전 방어하고 안정적인 서비스 루프를 보장했습니다.

  1. **문제 1: 정수형 형변환(Type Casting) 중 데이터 형식 불일치에 따른 ValueError 발생 및 런타임 붕괴**
     * **원인:** 학번 입력(`int(input())`), 좌석 번호 및 입·퇴실 시간 입력 파이프라인에서 사용자가 실수로 문자열이나 공백을 유입시켰을 때, 파이썬 인터프리터가 정수형 형변환을 처리하지 못해 `ValueError` 예외를 발생시켰습니다. 이로 인해 메인 `while True` 제어 루프가 강제로 파괴되며 키오스크 시스템 전체가 다운되는 결함이 발견되었습니다.
     * **해결:** 데이터 유입의 핵심 관문인 `setup_user_profile()` 및 `reserve_seat()` 함수의 입력부 전체를 `try-except ValueError` 블록으로 캡슐화했습니다. 비정형 데이터가 감지되면 예외 트랩을 통해 에러 메시지를 바인딩하고, `return` 제어문을 호출하여 런타임 환경의 크래시 없이 시스템 세션을 메인 메뉴 루프로 안전하게 회귀시켰습니다.
  2. **문제 2: 이중 리스트 데이터 백업 시 텍스트 스트림의 파일 포인터 조작 및 예외 처리 충돌**
     * **원인:** 메인 메뉴 4번 프로세스 종료 시퀀스에서 `with open()`을 통해 외부 디스크에 데이터를 기록(Write)하려고 시도할 때, 인코딩 불일치나 권한 제약 등으로 예기치 못한 입출력 예외가 발생할 경우 파일 포인터가 비정상적으로 닫히거나 데이터 유실과 함께 종료 프로세스가 멈추는 동기화 논리 에러가 발생했습니다.
     * **해결:** 파일 저장 연산부 전체를 상위 구조의 `try-except Exception` 블록으로 이중 보호 조치했습니다. 구문 내에서 데이터 스트림을 안정적으로 파일에 플러시(Flush)하도록 유도하고, 예외 발생 시 에러 트레이스를 가로채 콘솔에 명시적 디버깅 문구를 출력한 뒤 시스템 세션이 규정된 `break` 절차를 밟아 안전하게 프로세스를 커밋하도록 제어 위계를 재정렬했습니다.
